## What happened

Attackers spent months building a relationship with the Drift team, posing as a
trading firm and depositing about one million dollars to look real. Chainalysis
describes meetings at conferences and messaging platforms. That is the setup, not
the vulnerability.

The vulnerability is what came next. Solana has a feature called durable nonces.
Normally a Solana transaction goes stale quickly, which limits how long a signature
is worth anything. A durable nonce removes that limit, so a transaction can be
signed today and submitted later. The attackers built transactions that used this,
got Security Council members to sign them, and the signatures sat there.

On 2026-04-01 the attackers submitted them. The transactions handed admin control
of the protocol to attacker wallets, with entirely valid signatures.

With admin control they did the second half. They had created a token called CVT on
2026-03-12, kept most of the supply, and traded it against itself in a tiny pool to
manufacture a price near one dollar. As admin they added CVT to the list of accepted
collateral with very high borrowing limits, deposited 500 million of it, and made
thirty one withdrawals of real assets in about twelve minutes.

## Why it worked

Two separate failures, and it is worth keeping them apart.

**The signing failure.** The council members were asked "do you approve this", and
what they could see did not tell them what they were approving. This is blind
signing. It is the same problem as an approval workflow where the approver sees a
ticket number instead of the change, except here the signature was also good
forever.

**The configuration failure.** The admin role could add a new collateral asset and
set its borrowing limits by itself. There was no second control asking whether the
asset was real, whether its price came from a market with any depth, or whether the
limits made sense. So the moment the admin key moved, the protocol would happily
value a worthless token at one dollar because an oracle the attacker controlled
said so.

## What the fix is, and why the obvious fix would not work

The obvious fix is "do not let the council get socially engineered". That is not a
control, it is a wish. A six month operation run by people who show up at
conferences will beat awareness training.

The control that actually holds is on the signing surface. If the device or
interface renders what the transaction does in plain words, a transfer of admin
control does not look routine. If the authorisation expires, a signature collected
weeks early is worthless by the time it is used.

The second control is on the configuration path. Adding collateral is not the same
kind of action as a routine parameter tweak, and it should not travel on the same
key with the same speed.

Note for the reader: this entry does not comment on any token's value, only on how
a price was manufactured.
