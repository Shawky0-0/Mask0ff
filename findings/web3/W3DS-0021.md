## What happened

hono is a small web framework, widely used on edge runtimes, and it ships a memo() helper. memo()
means: if you call this component again with the same inputs, reuse the last answer instead of
rendering it again.

It decided "same inputs" by comparing the props that were passed in. Some components also read
values that were never passed in: the current request, the logged in user, the token for this
request. Those reads did not count towards the comparison.

So user A loads a page. The component renders A's version and it is cached. User B loads the same
page with the same props on the same server. The cache says "I have seen these inputs", and hands B
the HTML that was rendered for A.

## Why it worked

The framework isolated requests correctly. Each request had its own context. That was never the
problem.

The problem is one layer up. The cache decided reuse was safe using a key that did not include
everything the render depended on. A cache is only as correct as its key.

Rated moderate at 4.8, which is arguably low for cross user disclosure of another account's data
and of CSRF tokens, but the score is the advisory's, not mine.

## The fix, and why the obvious fix would not work

Upgrade. The patch is in 4.12.34.

The obvious fix, "clear the cache between requests", would work and would also delete the reason
the cache exists. The durable fix is the one the advisory implies by describing who was never
affected: pass every request specific value in as a prop, so it lands in the key. Make the hidden
input a visible input.

The reason this entry is here rather than in the web sibling folder is the test, not the package. A
dApp front end renders wallet addresses, balances and session state on the server, and this shape
leaks exactly that. But the test is a plain web test with two browser profiles, and Ahmed can run
it on the fleet tomorrow. See
MTH-W3-009.
