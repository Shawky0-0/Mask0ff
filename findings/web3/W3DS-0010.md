## What happened

On 2026-05-20, between 23:30 and 23:32 UTC, an account called `polymarketdev` published nine packages
whose names all read like official Polymarket tooling. Two were named for AI coding assistants.

Installing one ran a postinstall script. In an interactive terminal it printed a colourful banner
claiming the wallet key would stay encrypted, then took the key through a masked input field so it
looked like a normal password prompt. Whether or not anyone typed anything, the same script read the
`PRIVATE_KEY` environment variable and values from `.env` files. All of it was posted as plaintext JSON
to an endpoint on a Cloudflare Workers subdomain the attacker controlled, and a device identifier was
written to a local directory so the same machine could be recognised later.

## Why it worked

The registry gives no meaning to a name. `polymarket-terminal` is available to whoever types it first,
and to a developer looking for a Polymarket command line tool it reads as official. Nothing in the
install flow says who published it or whether the brand has anything to do with it.

Then the install step does something people forget it can do: it runs code, as them, with their
environment, on a terminal it can print to and read from. A prompt that appears during `npm install`
inherits the trust of the thing being installed. It looks like setup, not like an attack.

The masked input is the detail worth remembering. Asterisks signal "this is a password field, this is
handled carefully". Here they signalled the opposite of the truth, and the same script did not need the
prompt at all for anyone who kept a key in their environment.

## What the fix is, and why the obvious fix would not work

The obvious fix is to be careful about which packages you install. That fails in practice, because the
whole attack is built around a name that looks right at the moment you are looking for it, and because
the environment harvesting works even if nobody types anything.

The fix that actually holds is structural, and none of it is web3 specific. Disable install scripts by
default. Install in a container with no secrets and no egress, so a malicious script finds nothing and
can send nothing. Check the repository field before adding a dependency. Keep long lived credentials out
of shell environments and `.env` files on workstations entirely.

And keep one rule with no exceptions, because it is cheap and it is decisive: an installer that asks for
a secret is an attack.
