## What happened

A very widely used JavaScript crypto library had a function that produced random
bytes. From 2014 it produced them badly: a home made generator seeded from
`Math.random()`, which is not a cryptographic source. Asking for 128 bits of
randomness got you something a laptop can search.

Wallet applications used that function to build recovery phrases, the twelve or
twenty four word backup that is the wallet. So the phrases were guessable. The
research is named after the first vulnerable phrase found, which began "illness
blossom".

Five wallet applications are confirmed vulnerable by name, across fourteen chains.
The first confirmed on chain theft using this was 2026-05-27, with more through
July 2026.

## Why it worked

The wallets were not careless in any way an audit would flag. They called a
documented function from a mainstream library, and the function did exactly what
its name said. The gap was between two meanings of the word random: statistically
even, which the function delivered, and unguessable by an adversary, which it did
not. Nothing in the type signature or the name distinguishes those, so the
distinction has to live in the reviewer's head.

The second reason it lasted is that bad randomness passes every test that is not
looking for it. A weak seed phrase is a valid seed phrase. It has the right word
count, the right checksum, and it makes a working wallet. It behaves correctly
right up until somebody else guesses it.

## The fix, and why the obvious fix is not enough

The library replaced the generator in version 4.0.0 with the platform's own
cryptographic API. That fixes new keys.

It does nothing for the keys already made, and that is the part worth carrying
into the QA lane. Upgrading a dependency normally ends an incident. Here the
upgrade is only half of it, because the damage was written into user held secrets
years ago and no patch can reach them. Anything derived from a broken generator
has to be rotated, not patched, and the people holding those secrets have to be
told. This is the same shape as W3DS-0008, where the wallet vendor said plainly
that existing seeds cannot be repaired and must be replaced.
