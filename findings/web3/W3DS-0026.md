## What happened

On 2025-09-08 somebody published a poisoned version of `debug`, a tiny logging
package that thousands of other packages depend on. It was up for about two and a
half hours.

MetaMask's SDK depends on `debug`. The SDK itself was never touched. But anybody
who installed or updated the SDK during those two and a half hours pulled the
poisoned version along with it. The injected code tried to interfere with the
messages passing between a dApp and a wallet in the browser.

## Why it worked

The interesting part is not the malware. It is who got hit and why.

The advisory says only three groups were affected: people installing for the first
time with a lock file, people installing without one, and people who updated in a
way that pulled in that version. Everybody else, with an existing lock file
pinning an older `debug`, installed the same bytes they had installed the week
before and were untouched.

So the compromise was not decided by the code anyone wrote or reviewed. It was
decided by a file most teams treat as noise in a pull request, and by the clock.
Two developers on the same commit, running the same command ninety minutes apart,
got different software.

## The fix, and why the obvious fix is not enough

The SDK released 0.33.1 with the dependency corrected. The obvious response,
upgrading, is right and insufficient, because the next poisoned publish will be a
different package and will not have your SDK's name on it. What actually shrinks
the window is making the build reproducible: commit the lock file, install with
the command that refuses to resolve anything new, and treat a change in a
transitive version as something a human signs off, exactly as a code change is.
